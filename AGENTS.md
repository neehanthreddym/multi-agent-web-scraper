# Codex Working Rules

- Treat [PRD.md](PRD.md), [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md), and [ARCHITECTURE.md](ARCHITECTURE.md) as the accepted baseline.
- Read relevant files and applicable instructions through direct file-reading capabilities. Do not execute terminal commands, including Git, inspection commands, installations, scaffolding, builds, tests, or development servers.
- When a command is needed, provide the exact command, working directory, and expected result. Wait for the user to run it and share output, then inspect that output before relying on its result.
- Keep changes focused and achievable for one developer. Local implementation using the documented Python stack is authorized; follow the architecture implementation sequence. Do not provision services or change GitHub issues/project statuses without explicit authorization.
- Keep docs accurate when scope or behavior changes. Consolidate unresolved questions in the short architecture table; label defaults and assumptions.
- Enforce budgets and security in application code. Treat pages and model output as untrusted. Preserve original extraction, evidence, and review history. Never expose credentials.
- Report exactly what changed, what was verified, how it was verified, and remaining limitations. Never invent test results, model scores, or deployment success.
